# ドロピザ考察アーカイブサイト 設計（2026-07-28）

## 背景・目的

`doropiza`リポジトリには、YouTubeチャンネル「ドロピザ」のONE PIECE考察動画の要約が`ドロピザ考察001-030.md`〜`ドロピザ考察331-360.md`の12ファイルに、計214件蓄積されている。現状の閲覧手段はMarkdownファイルを直接開くのみで、特定の考察を探すには全文を目で追う必要がある。

`ai_news`・`investment`リポジトリで実践している「静的データ生成→カード一覧→タップで詳細モーダル表示」のパターンを踏襲し、214件の考察をフリーワード検索・タグ絞り込みで探せる自分用の閲覧ツールをVercelにデプロイする。

- 用途: 自分用の閲覧・検索ツール（公開URLだが認証なし。ai_news/investmentと同じ運用）
- 今後の更新: 不定期に手動でmdへ考察を追記する想定。日次自動化のような仕組みは不要
- デプロイ先: 既存の`doropiza`リポジトリ（GitHub: motoki4869/doropiza）に`site/`を追加し、Vercelと新規連携する

## 全体像

- 12個の`ドロピザ考察*.md`はそのまま情報源として使う。内容の書き換えはしない。
- 各mdファイル内の`## `見出し1つ＝考察1件として、ビルド時にパースしてJSONデータ化する。
- 見出しからキャラクター名/テーマのキーワードを拾い、タグを自動付与する（辞書ベース、精度100%は狙わない）。
- サイトはカード一覧＋フリーワード検索＋タグ絞り込みチップ＋タップで全文モーダル表示（ai_news方式）。
- ビジュアルは宝地図・海賊風テーマ（パーチメント背景、金・セピア・深緑/ワインレッドのアクセント）。ai_newsのネオン系とは意図的に差別化する。

## データフロー・コンポーネント構成

```
[ドロピザ考察*.md]（12ファイル、手動追記）
        ↓
scripts/generate_entries_data.py
  - 各mdの "## " 見出し単位でエントリ分割
  - 見出しから番号・タイトルを抽出（番号なし見出しは番号バッジなしで表示）
  - 本文をMarkdown→HTML変換（ai_news/scripts/generate_reports_data.pyのmd_to_html/parse_tableを流用）
  - tags.jsonの辞書と照合してタグ配列を付与（該当なしは「未分類」）
        ↓
site/data/entries-data.js （window.ENTRIES = [...] を生成・上書き）
        ↓
git add / commit / push
        ↓
Vercel 自動デプロイ（main push契機、Root Directory = site）

[ブラウザ]
  entries-data.js を読み込み → 検索バー/タグチップでフィルタ → カードグリッド描画
  カードタップ → モーダルで該当エントリの全文HTMLを表示
```

### 新規ファイル

- `scripts/generate_entries_data.py` … md→JSONデータ変換スクリプト
- `tags.json` … タグ名→マッチキーワード配列の辞書（リポジトリ直下、手で拡張可能）
- `site/index.html` `site/app.js` `site/style.css` … 静的フロント
- `site/data/entries-data.js` … 生成データ（gitコミット対象）
- `site/favicon.ico` 等 … `images/doropiza.png`から書き出すファビコン一式（既存の`images/doropiza.png`をロゴとしてヘッダーに使用）

### 既存ファイルへの変更

なし。`ドロピザ考察*.md`は読み取り専用の情報源として扱う。

## コンポーネント詳細

### `site/data/entries-data.js` のスキーマ

```js
window.ENTRIES = [
  {
    id: "031-060_002",              // ファイル名+ファイル内出現順（安定した一意キー）
    number: "302",                  // 見出しから抽出できた場合のみ。できなければ null
    title: "ゲッコー・モリアの真実：光月家の血脈と「人形」に隠された物語の核心",
    sourceFile: "ドロピザ考察301-330.md",
    tags: ["黒ひげ海賊団", "モンキー家/革命軍"],
    html: "<p>...</p>"
  },
  ...
];
```

- `id`: ソートファイル名の中の数値部分＋そのファイル内での出現連番から機械的に生成する。人間が読む番号（`number`）と役割を分離し、番号なし見出しでも一意性を保証する。
- `number`: 見出しが`## 302. タイトル`のような`## <数字>. `形式のときのみ数値文字列として抽出。単一漢字ラベル（`## 転:`等）や番号なしタイトルの場合は`null`。
- `tags`: `tags.json`の辞書とタイトル＋本文を照合して機械的に付与。複数タグ可、0件なら`["未分類"]`。

### `scripts/generate_entries_data.py`

- 引数なしで実行。リポジトリ直下の`ドロピザ考察*.md`をファイル名順（＝番号順）に全件読み込む。
- 各ファイルを行単位で走査し、`^## `にマッチした行を見出しとして次の見出し行の直前までを本文とする（`ai_news`のreportとは異なり1ファイル内に複数エントリがある点が構造上の違い）。
- 見出しテキストから`^(\d+)\.\s*(.+)$`にマッチすれば`number`と`title`を分離。マッチしなければ見出しテキスト全体を`title`とし`number`は`null`とする。
- 本文はai_newsの`md_to_html`/`parse_table`関数を移植して変換する（見出し・箇条書き・テーブル・強調に対応。doropizaの本文は`###`以下のネスト見出しを含まないことを確認済みなので、変換範囲はそのままで足りる）。
- 空本文の見出し（誤検出等）はスキップし、標準出力に警告を出す。処理は継続する。
- 実行のたびに全件を読み直して`entries-data.js`を丸ごと上書きする（差分計算はしない。ai_newsと同じ方式）。
- 実行結果として生成件数・警告件数を標準出力に表示する。

### `tags.json`

```json
{
  "ルフィ/ニカ": ["ルフィ", "ニカ", "ゴムゴムの実", "ヒトヒトの実"],
  "イム様/世界政府": ["イム様", "世界政府", "五老星", "天竜人"],
  "黒ひげ海賊団": ["黒ひげ", "マーシャル・D・ティーチ", "ロックス"],
  "モンキー家/革命軍": ["モンキー家", "ドラゴン", "革命軍", "ガープ"],
  "空白の100年/古代史": ["空白の100年", "ゴッドバレー", "古代兵器", "ジョイボーイ"],
  "他作品": ["推しの子", "アイシールド21", "ポケモン", "ディズニー"]
}
```

- 初期辞書は既存214件のタイトルを分析して抽出した主要キャラ・テーマ20〜25項目程度で開始する。
- リポジトリ直下に置き、今後キーワードを追記するだけでタグ体系を拡張できる（スクリプト・サイト側の変更は不要）。
- マッチはタイトル＋本文プレーンテキストに対する単純な部分文字列一致（大文字小文字・全角半角の正規化は行わない。日本語の固有名詞なので実用上問題ない想定）。

### フロント（`site/app.js`）

- `site/data/entries-data.js`を読み込み、全エントリを保持する。
- 検索バー（フリーワード）とタグチップ（複数選択、AND条件）でクライアントサイドフィルタする。
- フィルタ結果をカードグリッドとして描画する。カードには番号バッジ（`number`があれば）・タイトル・タグチップ・出典ファイル名を表示する。
- カードタップでモーダルを開き、`html`を全文表示する。モーダルは閉じるボタン・背景クリック・Escで閉じる。
- 214件のエントリ・タグ・検索語すべてクライアントサイドの配列操作で完結する規模のため、サーバー側処理やページングは設けない。

## ビジュアル設計

- コンセプト: 宝地図・海賊風。羊皮紙（パーチメント）の背景に金・セピア・深緑/ワインレッドのアクセント。
- 配色: `--parchment: #f0e0bd` `--ink: #2b1d0e` `--gold: #c9962c` `--wine: #7a1f2b` `--sea: #2b5a63`
- 背景はCSSグラデーションで羊皮紙の質感を表現し、画像アセットには依存しない。
- ヘッダーに`images/doropiza.png`のロゴを配置。
- カードは羊皮紙の切れ端風。番号バッジは丸い焼き印/蝋印風、タグチップは焼き印風。
- モーダル本文エリアは可読性を優先し、背景をシンプルな薄ベージュ単色にする。
- フォントは日本語対応の装飾的な見出しフォント＋可読性重視の本文フォントの組み合わせ（実装時にGoogle Fontsから選定）。

## エラーハンドリング・エッジケース

- 見出し直後に本文がない、または本文が空白のみ：そのエントリをスキップし、スクリプトの標準出力に警告として出す（サイレント無視しない）。
- 番号が重複・欠番：表示上は気にしない。ソート順は「ファイル名順→ファイル内出現順」に固定する（`number`でソートし直すことはしない。番号なしエントリが混ざるため）。
- `tags.json`のどのキーワードにも一致しない：`["未分類"]`タグを付与し、タグフィルタからも選択できるようにする。
- `ドロピザ考察*.md`が1つも存在しない：空の`entries-data.js`（`window.ENTRIES = []`）を生成し、サイト側は「データがありません」の空状態を表示する。

## デプロイ

- Vercelで新規プロジェクトを作成し、`doropiza`リポの Root Directory を `site` に設定する。
- GitHubリポジトリ（motoki4869/doropiza）と連携し、`main`へのpushで自動デプロイされるようにする。
- `vercel.json`は基本的に不要（静的ファイルのみで、Serverless Functionは使わない）。
- 公開URL、認証なし（ai_news/investmentと同じ運用）。

## テスト方針

- `scripts/generate_entries_data.py`をローカル実行し、生成件数が214件前後であること、`entries-data.js`が構文的に妥当なJSであることを確認する。
- 番号あり見出し・番号なし見出し・単一漢字ラベル見出しのそれぞれについて、想定通りパースされているかサンプルを目視確認する。
- ブラウザで実際に検索・タグ絞り込み・カードタップ→モーダル表示・モーダルを閉じる、の一連の操作を確認する。
- 自動テストは設けない（パースロジックが複雑化した場合は`investment/scripts/test_generate_site_data.py`同様の単体テスト追加を検討する）。

## 今後の更新フロー（運用）

1. `ドロピザ考察*.md`（既存ファイルへの追記、または新規ファイル）に考察を追加する。
2. `python3 scripts/generate_entries_data.py`を実行し、`site/data/entries-data.js`を再生成する。
3. 変更ファイルを`git add`・`git commit`・`git push`する。
4. Vercelの自動デプロイでサイトに反映される。

専用のClaude Codeスキルは設けない。ai_newsの`sync-news-html`と異なり、カードのキュレーションや上限循環がなく、全件を機械的に再生成するだけの単純な作業のため。
